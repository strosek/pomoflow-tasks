# 0023 — Tags (#tags)

Status: done

## Goal

Let the user tag tasks by typing `#tag` in the task title at creation, and see a tag-based
overview that highlights areas of work needing attention.

## Model

- Add `tags: string[]` to `Task`.
- At task creation, parse `#word` tokens from the entered title (e.g. `Write report #work`),
  normalize them (lowercase, trim surrounding punctuation) and store as `tags`.
- The `#`-token text can remain in the title or be stripped; tags are also shown as small chips
  on the task row either way.

## Requirements

- Display tags as compact, dim chips on each task row (unobtrusive in the minimal layout).
- Provide a tag overview that surfaces where attention is needed: count of **open** tasks per
  tag, sorted descending, so tags with the most unfinished work stand out.
- Tag parsing handles multiple tags in one title; a tag with no task and `#` alone is ignored.
- Keep tags editable at creation only for now (no separate tag manager) to avoid bloat.

## Acceptance criteria

- Creating a task with `#work #home` yields a task with those two tags and matching chips.
- A task with no `#` token has an empty tag list.
- The tag overview shows open-task counts per tag, most-attention first.
